# Pocket Paradox — project context

Saved 2026-09-14 from local source and documentation. Read this file when resuming work; source code is authoritative where design notes differ.

## Product and current state

Pocket Paradox is an original, offline Android spatial puzzle game inspired by the boxes-within-boxes mechanic of Patrick's Parabox. Players push crates and movable room boxes onto box goals, then reach the player goal. Blocked room boxes can be entered through centered doorways; exiting places a piece beside the containing box. Moving a room carries its contents.

Version 0.1.0 contains 12 puzzles in three chapters: First moves, Worlds within, Moving worlds. Includes home, puzzle selection, sequential unlocking, replay, best move counts, undo, restart confirmation, help, haptics, and confirmed progress reset. Controls support native direction buttons, swipes, arrows/WASD, and Z for undo. No backend, accounts, ads, analytics, network services, requested Android permissions, or third-party runtime dependencies.

## Architecture and flow

All main Java files are under `app/src/main/java/com/pocketparadox/game/`.

| File | Role |
| --- | --- |
| `Engine.java` | Android-independent deterministic rules, room/piece model, movement, rollback, containment validation, goals, undo, and versioned saves |
| `Levels.java` | Static campaign definitions, chapter names, hints, and winning solution transcripts |
| `MainActivity.java` | Single native Activity; programmatic screens, Canvas `Board`, input, accessibility descriptions, lifecycle, and SharedPreferences |
| `tests/EngineCheck.java` | Engine rules and malformed-save checks |
| `tests/LevelCheck.java` | Campaign solution replay and seeded invariant checks |
| `tests/android_smoke.py` | Emulator-only UI/lifecycle/campaign checks and screenshots |

Flow: `Levels.ALL` supplies a level → `MainActivity` constructs `Engine` → input calls `Engine.move` → recursive pushes/entry/exit either succeed or roll back → Activity records completion/best score/unlocking, persists state, and redraws. Keep spatial rules in Engine so they remain testable without Android.

Rooms use `#` wall, `.` floor, `o` box goal, `@` player goal. Piece ID 0 is the player. A piece's `room` identifies its current room; `inside` identifies its interior room, or -1 for a crate/player. Each nonroot room has one owner. Cyclic containment is rejected. Successful moves store snapshots for undo; failed moves preserve state.

Persistence uses SharedPreferences `pocket-paradox-v1`: `sessionLevel`, `session`, `unlocked`, `complete.<index>`, `best.<index>`, and `haptics`. Engine saves use `PP1` plus a SHA-256 level fingerprint, move count, and piece state. Invalid or mismatched saves are rejected without mutating the game. One current puzzle session is saved; undo survives configuration changes through the retained Engine but is not serialized across process restarts.

## Build and verification

- Java source target 17; use JDK 17+ and Android SDK 36.
- Gradle wrapper 8.14.3; Android Gradle Plugin 8.13.0.
- Application ID/namespace `com.pocketparadox.game`; min SDK 26 (Android 8.0), compile/target SDK 36.
- Configure `JAVA_HOME` and `ANDROID_HOME`, or SDK location in untracked `local.properties`.

```sh
./check.sh
./gradlew :app:assembleDebug
./gradlew :app:lintDebug
./gradlew :app:bundleRelease
```

## Constraints and future work

- Finite nesting only: no self-containing boxes, infinity spaces, eating/squeezing behavior, or duplicate room references. Campaign reaches two nested depths; rendering previews three depths, independently of engine nesting.
- English-only; dedicated nonvisual puzzle navigation, audio, a larger campaign, broader device testing, production application ID, release signing, and store publication remain future work.
- UI uses dark navy, coral player/actions, mint room boxes, violet crates, and gold goals with native system fonts. See `design/DIRECTION.md` for visual intent, but its example 18-puzzle count, chapter labels, and layout proposals do not describe the implemented 12-puzzle campaign exactly.
- When extending the campaign, update solution transcripts and review `MainActivity.showLevels`, which currently groups four levels per chapter. Level title/geometry/start-state changes affect save fingerprints.
- Preserve original assets/puzzles, offline behavior, validated saves, transactional movement, and accessibility basics. No new feature was requested or implemented in this summary session.
